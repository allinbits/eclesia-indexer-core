# Migrating to 4.0

4.0 makes the engine chain-agnostic. Everything Cosmos-specific moved out of `@eclesia/indexer-engine` into a chain adapter package, and the same engine now runs gno.land. For an existing Cosmos indexer the migration is two imports and one config line.

## Cosmos indexers

1. Install the adapter and switch the modules package:

   ```bash
   pnpm add @eclesia/chain-cosmos@^4 @eclesia/cosmos-modules-pg@^4 @eclesia/basic-pg-indexer@^4 @eclesia/indexer-engine@^4
   pnpm remove @eclesia/core-modules-pg
   ```

2. Pass the adapter and type the config on it:

   ```diff
    import { PgIndexer, PgIndexerConfig } from "@eclesia/basic-pg-indexer";
   +import { cosmos, CosmosAdapter } from "@eclesia/chain-cosmos";
   -import { AuthModule, BankModule, Blocks, StakingModule } from "@eclesia/core-modules-pg";
   +import { AuthModule, BankModule, Blocks, StakingModule } from "@eclesia/cosmos-modules-pg";

   -const config: PgIndexerConfig = {
   +const config: PgIndexerConfig<CosmosAdapter> = {
   +  chain: cosmos(),
      startHeight: 1,
      ...
    };
   ```

   `@eclesia/core-modules-pg@4.0.0` still exists as a re-export of `@eclesia/cosmos-modules-pg` so a half-migrated project builds, but it will not be published again.

3. Custom modules declare which adapter they run on:

   ```diff
   -export class GovModule implements Types.IndexingModule {
   -  indexer!: EclesiaIndexer;
   -  private pgIndexer!: PgIndexer;
   -  init(pgIndexer: PgIndexer): void {
   +export class GovModule implements Types.IndexingModule<CosmosAdapter> {
   +  indexer!: EclesiaIndexer<CosmosAdapter>;
   +  private pgIndexer!: PgIndexer<CosmosAdapter>;
   +  init(pgIndexer: PgIndexer<CosmosAdapter>): void {
   ```

   `Types.TxResult` moved to `@eclesia/chain-cosmos` as `TxResult`. Event names, payloads, `callABCI`, migrations and the module lifecycle are unchanged.

4. Event map augmentations no longer need the engine's base events:

   ```diff
    declare global {
   -  interface EventMap extends GovEvents, Types.Events {}
   +  interface EventMap extends GovEvents {}
    }
   ```

   The engine declares its own events and `@eclesia/chain-cosmos` declares `block`, `begin_block`, `tx_events`, `tx_memo` and `end_block`.

5. Tests and benchmarks that assigned a mock client to the engine use the adapter's `connect` option instead:

   ```diff
   -engine.client = mock;
   -engine.blockClient = mock;
   -engine.connect = async () => true;
   +const config = { ...config, chain: cosmos({ connect: async () => mock }) };
   ```

   `Mocks.createMockRpcClient` and `Mocks.MockRpcClient` moved from the engine to `@eclesia/chain-cosmos`. The engine's `Mocks` now holds the chain-independent `syntheticChain()` and the adapter contract checks.

## Removed

- `EcleciaIndexer` and `EcleciaIndexerConfig`, the misspelled aliases deprecated in 2.x.
- `Types.Events` no longer lists the Cosmos block events.

## Behaviour changes

- An RPC URL that cannot deliver block subscriptions (an HTTP endpoint on cosmjs, or any endpoint for a chain without a push channel) switches the run to polling with a warning, instead of failing after several restarts.
- Package versions jumped from 2.16 to 4.0 because 3.0.0 had already been published for the engine from an earlier branch.

## New: gno.land

```ts
import { PgIndexer, PgIndexerConfig } from "@eclesia/basic-pg-indexer";
import { gno, GnoAdapter } from "@eclesia/chain-gno";
import { Blocks, MessagesModule, PackagesModule, ValidatorsModule } from "@eclesia/gno-modules-pg";

const config: PgIndexerConfig<GnoAdapter> = {
  chain: gno(),
  rpcUrl: "http://127.0.0.1:26657",
  usePolling: true, // Tendermint2 has no block subscription; the engine polls
  minimal: false,   // the validators module needs the per-block validator set
  ...
};
const indexer = new PgIndexer(config, [new Blocks.FullBlocksModule(), new MessagesModule(), new PackagesModule(), new ValidatorsModule()]);
```

Known upstream issue: `@gnolang/tm2-rpc` 1.0.0 decodes bech32 through `@cosmjs/encoding`, which passes an unbounded length that `@scure/base` 2.3.0 and later reject. A fresh install fails on every `status()` call with `limit: expected safe integer, got Infinity`. Until tm2-rpc or cosmjs ship a fix, pin `@scure/base` to 2.2.0:

```json
{ "pnpm": { "overrides": { "@scure/base@>=2.3.0": "2.2.0" } } }
```

or, with npm, `{ "overrides": { "@scure/base": "2.2.0" } }`. Projects generated by `create-eclesia-indexer` already carry this override.
